# Backend dependencies, pinned to exact versions (T-DO-DEBT-1; DO-23).
#
# Every package is pinned with `==`, transitive ones included, so two installs
# from this commit resolve the same tree whenever they run. The unpinned file
# this replaced did not: T-DO-1's image, built weeks after the dev venv, picked
# up newer releases of eight packages (alembic, anthropic, anyio, greenlet,
# httpcore2, httpx2, psycopg2-binary, PyJWT, SQLAlchemy, uvicorn) without a
# single line of this file changing.
#
# The versions below were frozen out of *that image*, not out of the dev venv.
# They are the set the 376-test suite and T-DO-1's full click-through ran
# against; the venv's older set is the one nothing was verified on. Freezing the
# venv would have pinned the project backwards onto untested versions, which is
# the opposite of what pinning is for. The dev venv was upgraded to match this
# file instead, so the two are now in lockstep in the one direction that was
# actually proven to work.
#
# Two entries carry environment markers, copied from the upstream metadata that
# produced them, because the two environments legitimately differ: uvloop has no
# Windows build and colorama is Windows-only. Without the markers this file is
# uninstallable on one platform or the other, and a single flat list frozen from
# Linux would fail on every developer's machine.
#
# `pip` itself is deliberately absent (it differs — 26.2.1 in the image, 26.1.1
# in the venv). It is the installer, not a dependency; with every version below
# pinned exactly, the resolver's own version does not change what it resolves.
#
# To change a version, change it here and rebuild both the image and the venv —
# never `pip install -U` into one of them and leave this file behind.
